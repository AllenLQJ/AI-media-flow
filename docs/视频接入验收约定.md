# 视频接入验收约定

日期：2026-10-11。此文定义剩余验收条件，不声明视频已经可用。Hub 服务端由 Hub 项目实现，MediaFlow 不修改其代码或代替其访问生成服务。

## 当前阻塞

实际 stdio `get_capabilities` 仍返回 service_version=0.2.1；Muse 只有 `image.generate/muse:auto` 的 verified profile，没有 `video.generate`。`input_transports=[]`，图片参考输入也尚未验证。MediaFlow 已在项目内构建 ffprobe 并通过本地 MP4 文件与隔离流程检查，见 [本地 MP4 验收](2026-10-11-本地MP4验收.md)；没有派发真实视频任务，没有 Muse MP4 成品或完整视频质量结论。

视频生成和参考帧输入是分别验收的能力。先实现不带参考素材的短镜头文字生成即可推进视频基础闭环；图生视频、首尾帧控制和人物身份一致性不能由此推定。

## Hub 提供的能力与证据

1. 适配器识别属于原任务的明确视频成品及其完成状态，排除普通来源网址、预览图、缩略图和其他任务产物。完成回复或发送成功不等于视频成品完成。
2. 经服务实际支持的授权方式取回原始视频，登记稳定 artifact ID、task ID、MIME、大小、SHA-256 和授权传输描述。扩展真实 MP4 登记与校验；不只修改能力数组。
3. 提供经过有界真实试验的 `video.generate` profile：实际模型或明确约定的默认路由、verified 证据、最短支持时长、格式及必要参数。尺寸、帧率、运动控制、音轨和参考帧分别声明实际验证范围，不沿用图片 profile 的参数。
4. 证据包括原任务 ID、服务版本、试验日期、请求与完成状态、可播放 MP4 的元数据及哈希。底层模型未知时明确标注，不能填写猜测名称。
5. 继续保留 context 幂等、等待人工介入、原任务恢复和取消的不确定性。读取超时后查询原任务，不重新发送生成。
6. 若新增参考帧输入，另验收 host_id、可信输入根目录、大小与哈希、真正进入生成服务的附件，以及图片用途。仅将路径写进提示词不算上传。

能力试验由 Hub 项目独立记录；MediaFlow 正常生成入口仍要求已验证 profile 和严格文本审核，不能通过临时跳过门禁做探针。双方实际接口继续使用 [HubGateway v1 实施约定](HubGateway-v1-服务端实施约定.md)。

## MediaFlow 后续实际验收

1. 再次只读查询实际服务能力，确认对应模型、执行模式、参数、输出 `video/mp4` 和验证证据。
2. 本机 ffprobe 及可追踪本地 MP4 的容器、实际帧、视频流时长、尺寸和损坏/纯音频拒绝已验证；真实模型返回文件时仍需实际检查该成品编码、帧、元数据及请求匹配。程序文件检查不代替完整播放质量判断。
3. 在用户当前认可的风格与角色设定上整理一个短镜头。时长选择 profile 已验证的最短值，不预设四秒或其他模型的参数。视频生成次数单独有界，不增加当前图片工作流的次数，不声称尚未支持的参考帧已使用。
4. 冻结新的 MediaSpec 和视频模板，独立提交真实文本审核，校验审核指纹及政策版本，再通过 ReviewGate 委派一次生成。
5. 查询原 Hub task ID 至明确终态，调用 get_artifact；在 MediaFlow 独立目录验证身份、大小、哈希、格式、尺寸和请求时长并原子保存。损坏、缺失或错任务文件留在收集失败状态，不进入交付。
6. 实际播放整个视频，检查人物、动作、手部、发丝、服装、镜头、闪烁与连续性；记录操作者、问题及 `human_video_full`。抽帧只能记录覆盖范围，不能批准完整视频交付。
7. 质量通过后交付清单再次校验文件哈希；不通过则保存缺陷，新版本重新审核。单镜头不能证明跨镜头、跨视频角色一致性。

当前 CLI、分镜 schema、门禁、持久化、MP4 文件检查和人工复核入口已有本地验证，可以承载后续已验证能力；真实 Muse 视频端到端行为仍须执行上述验收，不能以图片或本地夹具回归代替。
