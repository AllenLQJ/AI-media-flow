# MediaFlow 开发计划

日期：2026-10-11。原规格见 ../Agent-Hub-多媒体生成系统-Codex实施说明.md。

## 已确认的决定

1. 当前 AI-media-flow 目录作为独立 MediaFlow 仓库；不复制 Hub 源码。
2. Hub 聊天实现服务端缺口，本聊天提供契约及客户端验收测试。
3. 先图片后视频，Muse 是首版启用的生成 Agent。
4. 总控、生成 Agent、模型可替换；业务层只依赖 HubGateway 和能力配置。
5. 项目 Skills 由本项目编写，媒体模板参考成熟项目；先真实出样再迭代，不以程序成功代替画面质量。
6. 首轮真实图片验证选择二次元人物，重点检查细节、风格和角色一致性。

## 开发起点证据与边界（历史）

- MediaFlow 开始时仅有规格文件，没有代码和 Git 仓库。
- 本机 Hub 位于 ../AI-Integration-platform；阅读起点 HEAD 为 5b52abbd785d884e22ac99fcce4e25b99b2f3035。
- Hub 已提供八个 MCP 工具、任务持久化、稳定 request_id 和冲突检测。
- list_agents 当前声明执行模式，未提供可用于媒体参数校验的已验证模型能力。
- Muse 最终回复与 source_urls 不是已下载的媒体 artifact。
- Hub 存在其他开发的未提交修改；运行服务与源码能力声明可能不同，集成必须记录实际服务版本。
- 本轮不修改、不重启 Hub 共享服务，不运行其他项目的生成或休眠验收脚本。

当前服务已升级到 0.2.1，图片实际审核、生成与文件取回已完成两版；完整目标逐项现状见 [完成条件核对](完成条件核对.md)，不能将上面的开发起点视为当前能力声明。

## 实施阶段

### A：契约和文档

- 完成本文件、Hub 服务端交接约定、运行说明与来源记录。
- 定义请求、审核、能力和附件 schema，固定 HubGateway v1。
- 交接文件是实现建议，Hub 实现后以双端契约测试确认，不推测接口已存在。

### B：本地业务与客户端

- Python 3.12 环境；MediaFlow 独立 SQLite，使用事务与版本检查。
- 草稿、冻结版本、审核、受控生成、收集、成品复核、交付和有限返工。
- 提交意图先落盘，MCP 响应丢失后恢复相同请求；并发放行只生成一个步骤记录。
- stdio MCP gateway；fake gateway 使用真实可解码的测试图片，只证明流程。
- CLI 提供 JSON 输出、状态、事件、恢复、取消和交接包；没有跳过审核参数。

### C：风险验证

- 无审核、拒绝、错误格式、指纹变化、政策变化、参考素材变化均阻止生成。
- 并发、响应丢失、进程重启、同键不同请求、未知状态及不确定取消。
- 文件签名、解码、大小、哈希、原子保存；错误文件不得进入交付。
- 复核覆盖范围显式记录；无视觉能力时等待人工复核。
- 不支持的媒体类型或参数直接报错，不静默丢弃。

### D：真实接口与图片闭环

- Hub 服务端交接完成后，先只读检查工具、服务版本与已验证能力。
- 真实提示词审核 → 最多一次首轮图片生成 → artifact 取回 → 文件检查 → 用户视觉复核。
- 记录 Hub task ID、请求指纹、真实路径、文件元数据与复核意见。
- 在接口等待期间继续完成本地测试；不把 fake 或历史结果登记为真实集成。

### E：视频与交接

- 数据模型预留镜头、角色引用、时长、运动与连续性；视频参数由模型能力决定。
- 首先验证一个短镜头。视频依赖 ffprobe 检查真实容器、视频流、时长和尺寸。
- 未通过视频能力验证时保持关闭；抽帧不能填写完整视频审核。
- 新总控仅凭持久化状态、CLI 和交接包恢复，不依赖原聊天。

## 扩展边界

- `controller_agent`：操作者标识，不参与底层生成器协议。
- `generator_agent`：通过能力选择目标，首版配置允许 muse。
- `model`：模型标识与能力 profile；未知模型不猜参数。
- 请求编译器是独立模块；模型变化产生新请求和新审核。
- HubGateway 是唯一连接边界，未来远程传输可替换实现。
- 首版不引入第二套执行队列、LangGraph、Redis 或外部数据库。
